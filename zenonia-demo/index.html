제노니아 시리즈의 A* 자동 길찾기와 서버·클라이언트 락스텝 경력을 설명하기 위한 별도 시연이다. A* 탐색은 실제 격자에서 경로를 계산하고, 서버와 두 클라이언트는 같은 입력 묶음을 각각 처리한다. 실제 프로젝트의 소스·화면·프로토콜이나 네트워크 접속을 재현한 것은 아니며 수치는 예시다.

12×9 격자에서 상하좌우 네 방향으로만 이동하며 한 칸의 비용은 1이다. A*는 시작점부터의 실제 비용 g와 목적지까지 맨해튼 거리 h를 더한 f=g+h가 가장 작은 열린 노드를 선택한다. 동점일 때도 정해진 순서를 사용한다.

이 조건에서 맨해튼 거리는 실제 남은 비용을 과대평가하지 않아 최단 경로를 찾는다. 장애물은 통과하지 않으며 파티 전사의 첫 대상까지 경로 비용은 실제 계산 결과 15다. 열린 후보·확정 노드·최종 경로는 탐색 기록에서 읽어 그린다.

전사·마법사·지원가로 구성한 AI 파티 3명이 몬스터 24마리와 싸운다. 각자 살아 있는 적까지의 A* 경로 비용을 계산해 도달 가능한 가장 가까운 대상을 고른다. 경로를 따라 정수 좌표로 이동하고, 장애물에 가려지지 않은 사거리에서 공격한다. 대상이 쓰러지면 다음 경로를 계산한다.

전사는 근접 공격, 마법사는 대상 주변 맨해튼 반경 1.5칸의 광역 공격, 지원가는 공격과 파티 전체 손실 HP 회복을 수행한다. 몬스터도 가까운 파티원을 공격한다. 피해·회복·처치 수는 실제 시뮬레이션 상태에서 표시한다. 전투 모델은 초당 10틱, 한 틱 이동은 25단위(한 칸의 1/4)다.

이 장면은 AI로 구동하는 별도 전투 시연이며 실제 3인 네트워크 플레이나 대규모 성능 검증이 아니다. 유닛 간 충돌·군중 회피·이동하는 적의 추격은 생략한다. 뒤의 락스텝 구간은 별도의 두 유닛 이동 시나리오로 입력 전달과 대기를 설명한다.

각 클라이언트가 틱 번호와 입력을 서버에 보낸다. 첫 틱에는 목적지 명령, 이후에는 명시적인 무입력(no-op)을 보낸다. 서버는 해당 틱의 두 입력을 모두 모은 뒤 고정된 순서로 묶어 각 클라이언트에 전달하고 자신의 게임 상태도 같은 묶음으로 계산한다.

입력에는 위치 스냅숏을 넣지 않는다. 각 모델은 같은 지도·규칙·입력 순서를 사용해 A*와 정수 이동을 각각 계산한다. 이는 릴레이형 락스텝의 한 가지 단순화된 구현이며 실제 제노니아 서버 구조를 단정하지 않는다.

예시 틱 18에서 클라이언트 B의 입력 전송을 1.5초로 늦춘다. 서버는 A의 입력만으로 그 틱을 진행하지 않는다. 입력 묶음이 오기 전에는 클라이언트도 다음 틱을 처리하지 않아 게임 이동이 멈춘다.

명령이 도착하면 같은 순서의 묶음을 처리해 이동을 이어 간다. 입력 지연·파이프라이닝·느린 클라이언트 제외·타임아웃 같은 실제 서비스 대책은 생략했다. 화면 속 캐릭터가 멈추는 것은 이 시연의 엄격한 입력 대기 규칙에 따른 결과다.

같은 벽시각에도 서버와 클라이언트의 최신 틱은 전송 지연으로 다를 수 있다. 영상은 세 모델이 모두 처리한 공통 틱의 전체 상태를 비교한다. 화면의 해시는 진단용 요약이며, ‘상태 일치’ 표시는 같은 틱의 전체 상태 비교 결과에서 나온다.

결정론적 입력 동기화는 같은 입력만으로 충분하지 않다. 초기 상태·지도·계산 규칙·처리 순서가 같아야 한다. 이 데모는 서로 다른 C++·Java·플랫폼 사이 결정론이나 실제 인터넷 환경을 검증하지 않는다.

용어 정리

A*
g+h를 기준으로 후보를 선택하는 경로 탐색 알고리즘이다.
g·h·f
g는 누적 비용, h는 남은 비용 추정치, f는 둘의 합이다.
맨해튼 거리
가로 차이와 세로 차이의 합이다. 이 데모의 네 방향·동일 비용 격자에 사용한다.
열린 목록
발견했지만 아직 확정하지 않은 탐색 후보다.
락스텝
같은 틱의 입력을 같은 순서로 처리해 각 모델이 게임 상태를 계산하는 방식이다.
no-op
해당 틱에 입력 변화가 없음을 명시하는 명령이다.
입력 묶음
한 틱에 필요한 플레이어 입력을 순서대로 모은 데이터다.
공통 틱
비교할 모든 모델이 처리를 완료한 동일 시뮬레이션 시점이다.
결정론
같은 초기 상태·데이터·입력·규칙과 처리 순서에서 같은 결과를 얻는 성질이다.
